# AGENTS.md — Cinematic Atmosphere: Bedrock

Minecraft Bedrock **resource pack** (lighting, atmosphere, volumetric fog, color
grading via Vibrant Visuals). No textures, models, sounds, UI, or gameplay
changes — ever. Windows + PowerShell 5.1 only.

## Verify (exact commands, run from repo root)

```powershell
.\tools\validate.ps1                 # offline static checks; must exit 0
.\tools\validate.ps1 -CheckOfficial  # + live check vs Mojang/bedrock-samples (needs network)
.\tools\test-negative.ps1            # proves verify-package.ps1 rejects bad packs
.\tools\build.ps1                    # validate → package → verify → re-validate (4 steps)
.\tools\fog-report.ps1               # fog density by height + reach in blocks vs vanilla
.\tools\water-report.ps1             # water profiles × surface colors
```

- `build.ps1` regenerates `dist/Cinematic_Atmosphere_Bedrock.mcpack`. Never
  hand-edit `dist/`; never commit a stale `.mcpack` (post-package validation
  fails the build if versions differ).
- `validate.ps1 -SkipArtifact` exists only for pre-package validation inside
  `build.ps1`. Final state is always validated *with* the artifact.

## PowerShell 5.1 gotchas (all caused real bugs here)

- `.ps1` files MUST be **UTF-8 with BOM**; without it 5.1 reads them as
  Windows-1252 and corrupts accents. JSON in `resource_pack/` must have
  **no BOM** and end with LF (both enforced by `validate.ps1`).
- Bool switches need colon syntax: `-Param:$true`. `-Param=$true` silently fails.
- `-join` binds tighter than `-eq`: always parenthesize (`(@($a) -join '.')`).
- `ConvertFrom-Json` silently drops duplicate keys — check them with an
  independent scanner, not the parser.
- `[System.IO.Compression.ZipFile]::CreateFromDirectory` writes `\` into ZIP
  entries; `build.ps1` creates entries manually with `/`.
- `validate.ps1` must not depend on `git` (it runs on plain extracted copies).

## Validator discipline (hard-earned)

- Every new check must be **proven to fail**: temporarily reintroduce the bad
  value, confirm exit 1 with the right message, restore. A check that never
  failed proves nothing (this happened twice: a regex that didn't match the
  real spacing, and a traversal that returned `$null`).
- Guard against empty checks: count evaluated values and fail if a declared
  rule matched nothing.
- Prefix throwaway variables in `validate.ps1` (e.g. `$cbaTw*`): `$f`/`$h`
  collided with script-level state and produced a misleading failure.
- Test files go in `$env:TEMP`, never in the repo. A `finally { restore }`
  that writes unconditionally can create stray files — verify `git status`
  is clean afterward.

## Truthfulness rules (non-negotiable)

- Never claim in-game validation, screenshots, or FPS numbers. The user does
  all in-game testing; all values here are statically verified starting
  points. Say so in releases and docs.
- Compare against the pinned reference `Mojang/bedrock-samples@v1.26.50.4`
  (stable; `1.26.60.*` are preview-only). Note the source (file + tag) for
  every vanilla number you cite.
- When you correct your own earlier claim in docs, say so explicitly with the
  evidence — don't silently rewrite.

## Domain facts that are easy to get wrong

- `render_distance_type: "render"` means `fog_start`/`fog_end` are a
  **fraction of render distance** (chunks × 16), not blocks. Always convert to
  blocks at 16 chunks before judging a value.
- Each biome keeps its own vanilla `format_version` (87× `1.21.120`,
  `sulfur_caves` 1.26.0, `dappled_forest` 1.26.50); never downgrade.
- `min_engine_version` is `[1, 26, 50]`. All 83 Overworld biomes get
  `cba:cubemap_overworld`; Nether (5) and End (1) never do.
- `tone_mapping.operator`, `orbital_offset_degrees`, `caustics`, `waves` must
  be identical across same-type files (not blendable). `waves.enabled` is
  `false` everywhere by art decision.
- All 89 `biomes/*.client_biome.json` are generated by
  `tools/generate-biomes.ps1` from `tools/biome-map.ps1` +
  `tools/vanilla-baseline.json`. Regeneration must be byte-identical
  (verify, don't assume). Non-visual components are reproduced verbatim.
- MIT in `LICENSE` covers only code/tools/original configs/docs; transcribed
  vanilla values are excluded (see `NOTICE`).

## Git + releases

- Branch `main`, repo-local identity only (global git identity is someone
  else's). Never force-push; never delete releases.
- Release flow: bump `resource_pack/manifest.json` → `build.ps1` → commit →
  push → `gh release create vX.Y.Z --target main` with the `.mcpack` asset →
  **download the asset back and compare SHA-256 byte-for-byte** before
  announcing. Past releases (v1.0.0+) stay untouched for comparison.
- User handles FPS/visual testing personally; in-game test criteria live in
  `docs/compatibility.md` §4.4. Open scope questions live in
  `docs/scope-decisions.md` (e.g. grass/foliage colors are out of scope,
  awaiting user decision).
